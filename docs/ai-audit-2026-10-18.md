# AI analyst audit — 18 October 2026

Scope: the question path (`api/ask.py` → `ask/engine.py` → `ask/agent.py` → `ask/gemini.py`
and `ask/tools.py`), checked against a live run on biomed.ultrasoft-systems.com.

## What was observed

- "How many unpaid invoices do we have?" took **71 seconds**: four Gemini rounds at
  15–25 s each on the free tier.
- The answer contradicted itself: a headline of **806** unpaid invoices over a breakdown
  table totalling **888**. The breakdown counted draft invoices, which the screens and
  the headline figure exclude.
- It answered beyond the question, adding supplier bills nobody asked about.
- A question in the evening ran **11 minutes** until the connection dropped.
- Biomed's Error Log showed a lookup failing on every use (`erpnext_count` was given an
  argument, `question`, that ERPNext does not take) and alert passes colliding.

## Findings and what was done

| # | Finding | Severity | Fix |
|---|---|---|---|
| 1 | The time limit was checked only between rounds; one slow reply, a run of retries or model switches, or a heavy ERPNext report could run for minutes. | Critical | One deadline for the whole question, held inside every Gemini call, retry and model switch; a lookup is not started without time for it; each lookup's database queries are capped (MariaDB `max_statement_time`); the page stops waiting at 150 s. |
| 2 | Every question went through the model, even ones the platform already answers. | High | `ask/quick.py`: plain questions about a defined figure are answered from the KPI engine in about a second, with no model call. |
| 3 | The model was told each figure's name but not its rule, so it made up its own filters. | High | The prompt now carries the exact rule behind all 85 figures, generated from the registry, and says to reuse them when breaking a figure down. |
| 4 | Raw data queries counted drafts and cancelled documents by default. | High | The loaded sets count submitted documents only unless drafts are asked for, as the screens do. |
| 5 | No order for choosing among 18 overlapping tools; descriptions contradicted each other. | Medium | A fixed order: defined figure → one database query that filters, groups, sorts and limits → records → names → live ERPNext → reports (slow, last). Descriptions aligned to it. |
| 6 | It widened answers to areas not asked about. | Medium | Answer the question asked; offer the rest as follow-ups. |
| 7 | Tool results up to 24,000 characters; the figure lookup returned engine internals. | Medium | Results capped at 12,000; figures return only what is quoted (value, unit, note, as-of). The figure lookup now also covers the 14 live ERPNext figures. |
| 8 | Extra arguments from the model crashed tools. | Medium | A tool receives only the arguments it takes. |
| 9 | No way to measure quality. | Medium | `ask/evaluate.py`: fifteen Gigmann questions with known right answers, timed and scored. |

## What the audit cannot fix in code

- **The free tier.** Twenty requests a day per model, slow replies and per-minute
  limits. No model on it will demo reliably. A paid tier is required.
- **The model's reasoning.** Gemini Flash on its lightest thinking setting is quick but
  shallow. A stronger model, or a deeper setting on a paid tier, is the next lever, and
  should be chosen by the scorecard below rather than by preference.

## Measuring it

```
bench --site biomed.ultrasoft-systems.com execute command_center.ask.evaluate.run --kwargs "{'limit': 5}"
```

Run the same fifteen on each candidate model; compare passes, median seconds and
lookups per question. Instant answers cost no requests; on a free key, run a few at a
time.
